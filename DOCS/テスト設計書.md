# テスト設計書 — Explainable Semantic Space Explorer

**プロジェクト名:** Explainable Semantic Space Explorer  
**版:** 1.0  
**作成日:** 2026-05-05

---

## 1. テスト方針

- 本プロジェクトの最優先事項は「説明可能性」と「再現性」であるため、UI の見た目や速度よりも **ロジックの数値的な正しさ・例外境界・インデックス整合性の保証** を重点とする。
- 外部 API を使用しないため、モックの目的はネットワーク遮断ではなく大容量実資産（83,823 語彙 × 300 / 384 次元）の排除による高速化に限定される。テストデータはすべてメモリ上で動的生成する。
- プロジェクト制約によりコサイン類似度の外部ライブラリ使用が禁止されているため、自前実装の正しさは既知ベクトルによる **解析解との一致・数学的性質の検証** によって担保する（`scipy` / `sklearn` との比較は使用しない）。
- テストは単一開発者が `unittest` + 手動確認で実施する。`pytest` 等の外部テストライブラリは導入しない。

---

## 2. テスト対象範囲

**対象**

- `core/embedding_loader.py`（資産ロード・manifest 整合性検証ロジック）
- `core/distance_metrics.py`（コサイン類似度・ノルムの自前実装）
- `core/similarity_engine.py`（Top-K 検索・モデル間比較・距離分布算出）
- `core/pos_filter.py`（品詞フィルタ・グループ化・異品詞率・同品詞内順位）
- `core/analyzer.py`（分布統計拡張・ヒストグラム・Z-score 付与・近傍安定性）
- `transforms/clustering.py`（コサイン KMeans・自前ノルム/正規化・再現性）
- `transforms/projection.py`（PCA / UMAP・寄与率・attach_clusters・再現性）
- `ui/app.py`（UI 操作フロー — 手動確認のみ）
- エラーケース（未知語・shape 不一致・top_k 不正値・インデックス飛びなど）

**対象外**

- Streamlit フレームワーク自体の挙動
- `data/` 配下の実データファイルの内容（テストは動的生成モックを使用）

## 3. テストレベル定義

### 単体テスト

| 項目 | 詳細 |
|------|------|
| 対象 | `core/` 各クラスの個別メソッド |

| タイミング | 各モジュール実装完了後 |
| 合格基準 | 全テストケース PASS |

### 結合テスト

| 項目 | 詳細 |

| 合格基準 | 検索結果が正しく返却され、スコアが `[-1.0, 1.0]` 範囲に収まること |

| 項目 | 詳細 |
|------|------|

| タイミング | デプロイ前の最終確認 |

## 4. テスト環境

**ローカル環境**

| 項目 | 詳細 |
|------|------|
| OS | macOS（開発機） |
| Python | 3.12（venv） |
| 実資産 | テスト実行時不要（動的生成モック使用） |
| 外部 API | 使用しない |

**テスト構成**

- `tempfile.TemporaryDirectory` を使用して一時的なモック資産（`embeddings/`・`metadata/`・`manifest.json`）を生成し、テスト分離を実現する（`tests/test_embedding_loader.py` の `setUp` / `tearDown` 参照）。
- 実行コマンドは以下に統一する。

```bash
venv/bin/python3 -m unittest discover tests/ -v
```

**Streamlit デプロイ後確認**

- デプロイ後は UI を手動操作してシステムテストを実施する。

## 5. テストデータ方針

### テストファイルごとのデータ生成方式

| テストファイル | データ生成方式 |
|--------------|--------------|
| `tests/test_distance_metrics.py` | 実資産不使用。既知ベクトル（解析解が確定するもの）と `numpy.random.default_rng(seed)` による乱数ベクトルを混在させて使用。 |
| `tests/test_embedding_loader.py` | `_build_mock_assets()` ヘルパで `n=5` 程度のミニ資産を `tempfile.TemporaryDirectory` に動的生成。shape / dtype / vocab を引数で個別上書きでき、異常系シナリオを宣言的に記述できる。 |
| `tests/test_similarity_engine.py` | `_make_engine()` ヘルパで `n=6, dim=4` 等の小規模ベクトルを `numpy.random.default_rng(seed)` で生成し、`SimilarityEngine` を直接組み立てる。 |
| `tests/test_pos_filter.py` | `_make_result()` / `_sample_results()` ヘルパで NOUN×3 / VERB×2 / ADJ×1 の SearchResult を直接構築。実資産不使用。 |
| `tests/test_analyzer.py` | `_make_distribution()` ヘルパで `get_distance_distribution()` の戻り値を模した dict を生成し、SearchResult との組み合わせを検証。 |
| `tests/test_clustering.py` | `_random_vectors()` 乱数生成と、3 中心の `_separable_vectors()` でクラスタリング正当性を検証。同一 seed の完全再現性を確認。 |
| `tests/test_projection.py` | `_random_vectors()` で n=20, dim=8 の小規模行列を生成。UMAP は計算コストを抑えるため小規模に限定し、PCA / UMAP 共通で seed 固定下の再現性を確認。 |

**テストデータ原則**

- 永続的な `fixtures/` ディレクトリは作らない（再現性は seed 固定で担保する）。
- 一時ファイルは `setUp` / `tearDown` で確実に破棄する。

## 6. 合格基準

### 単体テスト

- 全テストケースが PASS（エラー 0・失敗 0）であること。
- `l2_norm`・`cosine_similarity`・`cosine_similarity_batch` が解析解（`[3,4]` のノルム = `5.0`、平行ベクトル = `1.0`、直交 = `0.0`、逆方向 = `-1.0`）と一致すること。
- 以下のカスタム例外が想定された境界条件で確実に送出されること。

| 例外クラス | テスト対象シナリオ |
|---|---|
| `VectorDimensionError` | 次元不一致・1 次元配列以外の入力 |
| `ManifestViolationError` | shape / dtype が `manifest.json` と不一致 |
| `IndexAlignmentError` | vocab 件数 ≠ pos 件数、インデックス飛び、インデックス重複 |
| `FileNotFoundError` | `manifest.json` 欠落、`static_vectors.npy` 欠落、ルートディレクトリ不在 |
| `UnknownWordError` | 語彙外単語の検索 / 比較 / 距離分布要求 |
| `InvalidTopKError` | `top_k=0`、負値の指定 |

### 結合テスト

- `SimilarityEngine.search` の返却件数が要求した `top_k` と一致すること。
- 類似度スコアが `[-1.0, 1.0]` の範囲に収まること。
- 検索結果が類似度降順で並んでいること。

### システムテスト

- クエリ語入力 → 類似語表示 → コサイン内訳表示のフルフローがエラーなく完了すること。
- 語彙外単語の入力時に適切なエラーメッセージ（E002）が表示されること。
- Streamlit 4 タブすべてに遷移できること。

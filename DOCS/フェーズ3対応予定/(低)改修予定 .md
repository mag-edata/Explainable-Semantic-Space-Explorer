# （低）改修予定

優先度「低」（リファクタリング・コード品質）の課題 25 項目を集約。詳細・優先度判断の根拠は `改修概要.md` を参照。

---

## 1. データ整合性関連（残）

### 1.3 `manifest.json` の `training_date` プレースホルダー残存

- **場所:** `data/manifest.json:9`
- **現象:** `"training_date": "YYYY-MM-DD"` がそのまま入っている。生成スクリプト `data_pipeline/manifest.py:71` のリテラル。
- **影響:** 整合チェックには無関係だが、外部公開ファイルとしての完成度を損なう。
- **対応:** `manifest.py` で `datetime.date.today().isoformat()` を埋め込むか、フィールド自体を削除する。

## 3. UI / Streamlit 関連（残）

### 3.2 Tab 1: 品詞フィルタ指定時の `heterogeneity_rate` 例外

- **場所:** `ui/app.py:209-261`
- **現象:**
  - サイドバーで `pos_filter` を "verb" などに指定し、結果が 0 件の場合 `static_engine.search` は空リストを返す。
  - その後の `POSFilter.heterogeneity_rate(static_results, query_pos)` が `ValueError("results が空です")` で UI を停止させる。
- **`UnknownPOSTagError`** も同種の懸念: `POSFilter.filter` 経由で品詞絞り込みすると、該当なしで例外が立つ仕様（Engine 側は静かにフィルタするので Engine 経由なら起きない。混在に注意）。
- **対応:** UI 側で結果数 0 件を `st.warning` で先にハンドリングしてから後続処理に進む。

### 3.3 Tab 1: 「異品詞率」の意味的ねじれ

- **場所:** `ui/app.py:255-261`
- **現象:** `pos_filter` で品詞を絞り込むと、検索結果は全件同じ品詞になる。その状態で `heterogeneity_rate(...)` を計算すると常に 0.0 か常に 1.0（query_pos がフィルタ対象と一致するか否か）になる。
- **影響:** 「異品詞率」の指標としての意味を持たない値が表示される。利用者の混乱を招く。
- **対応:** 異品詞率は `pos_filter is None` の場合のみ表示する（または `pos_filter` 適用前の results に対して計算する）。

### 3.5 Tab 4: `index_to_word` の重複構築

- **場所:** `ui/app.py:429`
- **現象:** `index_to_word: dict[int, str] = {v: k for k, v in loader.vocab.items()}` を毎回ループで構築。
- **問題点:** `SimilarityEngine._index_to_word` がすでに同等のリストを保持している（が `_` 始まりなので公開していない）。
- **対応:** `SimilarityEngine` に `index_to_word(idx)` メソッドを公開するか、UI 側でも `@st.cache_resource` でこの辞書を1回構築する。

### 3.6 `loader.pos[loader.vocab[query_word]]` の型

- **場所:** `ui/app.py:255`
- **現象:** `numpy.str_` 型がそのまま `query_pos: str` に代入されている。`POSFilter.heterogeneity_rate` 内の比較では問題なく動くが、型ヒントとの不整合がある。
- **対応:** `str(loader.pos[...])` に明示キャスト。

## 4. 投影 / クラスタリング層

### 4.1 `transforms/projection.py` の unused import

- **場所:** `transforms/projection.py:26`
- **現象:** `from dataclasses import dataclass, field` で `field` を import しているが未使用。
- **対応:** `field` を削除。

### 4.2 PCA の入力次元 D < 2 を検証していない

- **場所:** `transforms/projection.py:313-338`
- **現象:** `_validate_inputs` は `vectors.ndim != 2` と `shape[0] >= 2` を検証するが、`shape[1] >= 2` の検証がない。
- **影響:** `PCA(n_components=2)` に D=1 の行列を渡すと sklearn 側で例外（`n_components > min(n_samples, n_features)`）。エラーメッセージが分かりにくい。
- **対応:** `_validate_inputs` で `vectors.shape[1] >= 2` を明示チェック。

### 4.3 `KMeansClusterer._normalize_rows` の float64 アップキャスト

- **場所:** `transforms/clustering.py:291`
- **現象:** `unit_matrix: np.ndarray = matrix.copy().astype(np.float64)` で float32 を float64 に拡大。
- **影響:**
  - 全語彙 (83823 × 384) を投げる場合は約 256 MB が 512 MB に膨張。Streamlit Cloud のメモリ枠（無料: 1 GB）でギリギリ。
  - ただし UI Tab 4 は近傍 Top-K のみを渡すので致命的ではない。
- **対応:** float32 のまま正規化する。または `astype` の理由をコメントで明示。

### 4.4 sklearn `KMeans` の `n_init` 未指定

- **場所:** `transforms/clustering.py:191-195`
- **現象:** `KMeans(n_clusters=..., random_state=..., max_iter=...)` で `n_init` を指定していない。
- **影響:** sklearn 1.4 以降は `n_init='auto'` が既定だが、将来の sklearn バージョンで挙動が変化する可能性。
- **対応:** `n_init=10`（既存の慣習値）を明示。

### 4.5 距離計算ロジックの重複

- **場所:** `transforms/clustering.py:248-267` と `core/distance_metrics.py:191-198`
- **現象:** 両モジュールで `np.sqrt((matrix * matrix).sum(axis=1))` を独自に実装している。
- **影響:** バグ修正時に片方を直し忘れる温床。
- **対応:** `clustering.py` から `DistanceMetrics` の同等メソッドに委譲する（依存方向は OK: transforms → core はあり得るが現在は逆参照していない）。

## 5. core/ 層

### 5.1 `cosine_similarity_batch` の docstring に dtype 不整合

- **場所:** `core/distance_metrics.py:179`
- **現象:** docstring に `"dtype は float64"` と書かれているが、実装は `matrix @ query` の出力 dtype に従う。`matrix` が float32 なら結果も float32。
- **対応:** docstring を「dtype は入力に従う」に修正、または明示的に `.astype(np.float64)` する。

### 5.2 `SimilarityEngine.search` の `pos_filter` 戻り値の `rank` が連続でない

- **場所:** `core/similarity_engine.py:255-260`
- **現象:** `pos_filter` でフィルタすると、残った要素の `rank` フィールドは元の Top-K 順位(飛び飛び)のまま保持される（例: rank=1, 4, 7, ...）。
- **判断:** これは設計意図（全体順位を保持）であり、`pos_rank` を別フィールドで持つことで対処している。ただし **UI 表示上は「順位」列が飛び飛びになり利用者が混乱しうる**。
- **対応:** UI 側で「全体順位」「絞込順位」を別列にするか、rank の意味を補足するヘルプテキストを追加。

### 5.3 `EmbeddingLoader.vocab` の型ヒントが Optional

- **場所:** `core/embedding_loader.py:118`
- **現象:** `self.vocab: Dict[str, int] | None = None` で初期化し、`load_all()` 後にのみ非 None になる。利用側は毎回 None チェックが必要(実際には `load_all` 必須前提でチェックを省略している)。
- **対応:** `load_all()` を `__init__` 内で呼ぶか、`from_path` クラスメソッドを提供して構築完了状態のみを公開する。

## 6. data_pipeline/ 層

### 6.1 `train_w2v.py` 内で `merge()` が再実行される

- **場所:** `data_pipeline/train/train_w2v.py:114`
- **現象:** `load_corpus()` が `vocab = set(merge())` で `merge.py` を再呼び出し。一方、README のセットアップ手順では `python -m data_pipeline.vocab.merge` を先に実行している。
- **影響:** Brown コーパス読み込み・Wikipedia ダウンロードが train 実行時にもう一度走る（merge.py が `vocab.json` を読まずに再構築する設計）。
- **対応:** `merge()` を `vocab.json` を読みに行く軽量関数に変更するか、`load_corpus()` 内で `vocab.json` を直接読む。

### 6.2 `data_pipeline/__init__.py` に記載される実行順序の不正

- **場所:** `data_pipeline/__init__.py:6-10`
- **現象:** docstring の手順 3 で `export.static_vectors / contextual_vectors / vocab_pos` を並列に列挙しているが、`static_vectors.py` は `train_w2v.model` への依存があるため、**学習を完了させた後でないと実行できない**。
- **対応:** docstring の順序を「2. train → 3. export.static_vectors → 4. export.contextual_vectors → 5. export.vocab_pos」と段階明示。

### 6.3 vocab.json の構造ドキュメント不整合

- **場所:** `core/embedding_loader.py:213-220` と `data_pipeline/vocab/merge.py:50`
- **現象:**
  - merge.py が書き出す形式: `{"vocab": ["word0", "word1", ...]}`
  - EmbeddingLoader は両形式（list 形式と `{word: idx}` 辞書形式）をサポート
  - しかし、辞書形式を書き出すスクリプトはどこにもない
- **対応:** EmbeddingLoader 側のフォールバック分岐（`else: self.vocab = raw`）を削除し、リスト形式のみサポートと明示する（YAGNI）。

## 7. テスト網羅性

### 7.1 `ui/` のテスト 0 件

- **対象:** `ui/app.py`（537 行）
- **欠落:** `results_to_df` などの純粋関数すら未テスト。
- **判断:** Streamlit UI 自体は spu test しにくいが、データ変換ヘルパーは独立してテスト可能。

### 7.2 `data_pipeline/` のテスト 0 件

- **対象:** `data_pipeline/_common/tokenizer.py`, `_common/token_definition.py`, `vocab/`, `train/`, `export/vocab_pos.map_pos_tag` など
- **欠落例:**
  - `normalize_tokens(["Hello", "WORLD", "123abc", "!"])` の挙動テスト
  - `tokenize_text` の vocab フィルタ挙動
  - `map_pos_tag("NN") == "noun"` 等のマッピング表テスト
- **対応:** 純粋関数の単体テストを追加（外部依存のない箇所のみ）。

### 7.3 「192 テスト全通過」のラベル更新リスク

- **場所:** README.md, CLAUDE.md, 詳細設計書.md
- **現象:** 192 テストという数値が複数箇所にハードコードされている。テスト追加時に 3 箇所更新が必要。
- **対応:** README は「数値」より「単体テストで core / transforms 層を網羅」程度の表現に緩めるか、CI で数値を自動更新する。

## 8. その他の細かい点

### 8.1 `.DS_Store` がリポジトリ各所に存在

- **場所:** `core/`, `tests/`, `transforms/`, `data_pipeline/`, `data/` など
- 拡張属性付きで残っている。`.gitignore` で除外されているか要確認（macOS 固有のメタファイル）。

### 8.2 `core/__init__.py` が空

- 公開 API の集約がされていない。`from core import EmbeddingLoader, SimilarityEngine, DistanceMetrics, ...` ができない。意図的なら問題ないが、設計書には `core/` のクラス一覧が示されているので、`__all__` で明示するとインポート負担が減る。

### 8.3 `unique_pos` UI 表示

- **場所:** `ui/app.py:140`
- `vocab_pos` の値域は `["adjective", "adverb", "any", "noun", "verb"]` の 5 値のみ。`"any"` は接続詞・前置詞・限定詞・代名詞などすべてを含む雑なラベルで、フィルタとしての意味が薄い。利用者にとっては「どの品詞が含まれるか」が不透明。
- **対応:** UI に「any = 上記4品詞以外（接続詞・前置詞・限定詞など）」のヘルプを追加するか、より細かい coarse-grained POS（`"function"` 等）を用意する。

### 8.4 検索ボタンがない（自動検索）

- **場所:** `ui/app.py`
- **基本設計書 §2.1** には「ボタン: 検索実行」と記載されているが、実装は **入力即座に検索** している。設計書と実装の乖離。
- **対応:** いずれかに揃える。即時検索は UX が良いが、毎キーストロークで 5〜10 秒の計算が走るので逆効果になる可能性あり。デバウンス or ボタン化が望ましい。

### 8.5 データ拡張

- **対象:** `data/metadata/vocab.json`（83823 語）
- **状態:** 未着手
- **内容:** 語彙数・コーパス追加。フェーズ 3（改善）の項目。

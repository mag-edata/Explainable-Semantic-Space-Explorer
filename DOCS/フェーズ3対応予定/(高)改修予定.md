# （高）改修予定

優先度「高」の課題 4 項目を集約。詳細・優先度判断の根拠は `改修概要.md` を参照。

---

## 1.1 `vocab.json` と `static_vectors.npy` の件数乖離リスク

- **場所:** `data_pipeline/export/static_vectors.py:72-77`
- **現象:** `for word in vocab: if word in model.wv:` で **Word2Vec 語彙にない単語をスキップ** している。
  - その結果、`static_vectors.npy.shape[0]` が `len(vocab)` より小さくなる可能性がある。
  - `EmbeddingLoader._validate()` は N 一致を必須にしているため、起動時に `IndexAlignmentError` で停止する。
- **発生条件:** `train_w2v.py` の `min_count=5` フィルタにより、`vocab.json` 中の単語が Word2Vec 学習結果から脱落した場合。
- **現状回避できている理由:** 偶然 `min_freq=10`（vocab 生成側）≧ `min_count=5`（Word2Vec 側）になっているため、現データではほぼ全語が wv に存在している可能性が高い。しかしこれは保証ではない。
- **推奨対応:**
  - `valid_words` を vocab.json として書き戻す（vocab を Word2Vec の語彙に揃える）
  - もしくは `static_vectors.py` の冒頭で `assert set(vocab).issubset(model.wv.key_to_index.keys())` のガードを入れる

## 3.1 起動カレントディレクトリ依存

- **場所:** `ui/app.py:71`
- **現象:** `data_root = Path("data")` は **相対パス**。Streamlit Cloud や別ディレクトリからの起動で失敗する。
- **対応:** `Path(__file__).resolve().parent.parent / "data"` で絶対パスにする（`data_pipeline/` の各スクリプトと同様の解決方式）。
- **デプロイブロッカー候補:** Streamlit Cloud で working directory がプロジェクトルート以外になる構成では起動不能になる。

---

## 3.4 タブ間で `get_distance_distribution` を重複呼び出し

- **場所:** `ui/app.py:216, 303, 310, 341, 342`
- **現象:** 同一クエリ語に対して `static_engine.get_distance_distribution(query_word)` が **Tab1 / Tab2（2回） / Tab3（2回）** で計5回呼ばれる。`compare()` も内部で `search` を 2回呼ぶ。
- **影響:** 1 回 = 83823 × 300/384 のバッチ演算なので、ローカル CPU で **1クエリ実行に5秒〜10秒** 掛かる。要件定義書 NFR「Top-K + 距離分布算出 5秒以内」を超過しうる。
- **対応:**
  - `@st.cache_data` で `(query_word, engine_id)` をキーにキャッシュ
  - もしくは `main()` の上部で 1 回ずつ計算して各 Tab に渡す
- **既存 `@st.cache_resource` はエンジン本体のキャッシュであり、計算結果はキャッシュしていない。**

## 9.2 `data/` 大容量問題による Streamlit Cloud デプロイブロッカー

- **対象:** `data/embeddings/static_vectors.npy`（約 96 MB）, `data/embeddings/contextual_vectors.npy`（約 123 MB）
- **現象:** 埋め込みファイルが Git 標準の管理サイズを超えるため、`.gitignore` で除外している。これにより Streamlit Cloud に push しただけではデータが届かず、デプロイ完了しない。
- **影響:** 現在 Streamlit Cloud デプロイ未完了。フェーズ 2（デプロイ）の最重要ブロッカー。
- **検討中の解決策:**
  - Git LFS で大容量ファイルを管理
  - HuggingFace Hub に資産をアップロードし、Streamlit Cloud 起動時に取得
  - リポジトリ外のクラウドストレージ（S3 等）から起動時取得
- **方針:** 解決策確定後、即デプロイする。

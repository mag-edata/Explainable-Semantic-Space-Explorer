## 1.2 品詞タグ付けの「文脈喪失」問題

- **場所:** `data_pipeline/export/vocab_pos.py:124`
- **現象:** `pos_tag(vocab)` がソート済み単語列（`['a', 'aaron', 'abandon', ...]`）に対して NLTK の品詞タガーを適用している。
- **問題点:** NLTK の `averaged_perceptron_tagger` は **文脈依存**（前後の単語から品詞を推定）するため、辞書順に並んだ単語列に対するタグ付けは誤判定が生じる。
  - 例: "bank" が辞書順で "balance, bank, banker" の文脈に置かれても、自然言語の文脈ではない。
  - 単語単位で「最も典型的な品詞」を得たいなら、`nltk.pos_tag([word])` を語ごとに呼ぶか、複数文の中で出現位置を特定して投票するなどの工夫が要る。
- **影響:** `loader.pos` の精度が低下し、UI の品詞フィルタ・異品詞率指標の意味が弱まる。
- **未記載のため、説明可能性ツールとしての品詞情報の信頼性に留意要。**

## 1.4 静的ベクトルと文脈ベクトルの正規化状態の非対称

- **場所:** `data_pipeline/export/contextual_vectors.py:82` vs `data_pipeline/export/static_vectors.py`
- **現象:**
  - `contextual_vectors.npy` は `normalize_embeddings=True` で **L2 正規化済み**で保存される。
  - `static_vectors.npy` は **正規化なし**（Word2Vec の生ベクトル）。
- **影響:**
  - コサイン類似度の値そのものは `cosine_similarity_batch` 内で各行のノルムを毎回計算するため正しく算出される。
  - しかし `explanation` 辞書で出力される `dot_product` / `norm_a` / `norm_b` の **絶対値が両モデルで非対称**になる。
    - 文脈側: `norm_a ≈ norm_b ≈ 1.0`、`dot_product ≈ similarity`
    - 静的側: `norm_a / norm_b` は実値、`dot_product` は大きな値
  - UI 上で「内訳」を比較する際に、利用者が読み取りづらい。説明可能性ツールとしての主張と矛盾する側面がある。
- **方針候補:**
  - 両者を統一（両方を保存時に正規化、または両方非正規化）
  - もしくは UI / docstring で「文脈側はオンメモリで正規化済み」と明示する

## 2.1 Word2Vec 学習時に `seed` 未指定 + `workers=4`

- **場所:** `data_pipeline/train/train_w2v.py:126-133`
- **現象:**
  ```python
  model = Word2Vec(
      sentences=corpus,
      vector_size=300,
      window=5,
      min_count=5,
      workers=4,
      sg=1,
  )
  ```
  - `seed=` パラメータが指定されていない（gensim のデフォルトは `seed=1` で動くが、明示が CLAUDE.md「絶対制約 5」に必要）
  - `workers=4` は **gensim 公式ドキュメントで「seed を指定しても完全再現しない」** とされている。完全再現を保証するには `workers=1` かつ `PYTHONHASHSEED` を環境変数で固定する必要がある。
- **影響:** `static_vectors.npy` を再生成すると微妙に異なるベクトルが出力される可能性がある。デプロイ後に「再生成すると結果が変わる」現象が起きうる。
- **対応:** `seed=42, workers=1` で明示する（学習時間とのトレードオフ）。

## 2.2 UMAP の `n_neighbors` 既定値 vs サンプル数

- **場所:** `transforms/projection.py:297`
- **現象:** `UMAP(n_components=2, random_state=self._seed)` で `n_neighbors` が UMAP の既定値（15）。
- **問題:** `ui/app.py` の Tab 4 では「クエリ + Top-K 近傍語」のみを投影する。`top_k=10` の場合、サンプル数 = 11 < 15 となり、UMAP が **警告を出す（`n_neighbors is larger than the dataset size`）** か、内部で自動調整する。
- **影響:** UI ログに警告が出る・投影結果が不安定になる。
- **対応:** `n_neighbors=min(15, n_samples - 1)` を `_fit_umap` 内で動的に指定する。

## 9.1 [UI] 投影・クラスタタブ: クエリ語マーカーの凡例と図の不一致

- **ファイル:** `ui/app.py`（投影・クラスタタブの散布図、Tab 4）
- **現象:** `alt.Shape` + `alt.Scale(domain, range)` でクエリ語を `"cross"` に指定しているが、Altair の凡例表示と図上のマーカー形状が一致しない。
- **試みた失敗策:**
  - `range=["star", "circle"]` → Vega-Lite の無効値となり凡例自体が消滅
  - チャートをレイヤー分割（近傍語・クエリ語を別 `alt.Chart`）→ 描画自体が消えた
- **現在の状態:** `range=["cross", "circle"]` で保留中
- **次の候補解決策:**
  - `shape` エンコーディングを廃止し `size` + `color` でクエリを強調
  - Vega-Lite 有効値（`"diamond"` / `"triangle-up"` 等）を `range` に渡す
  - Vega-Lite SVG パス文字列を `range` に直接渡す
  - `mark_rule` / `mark_point` を組み合わせてクエリ点を別途オーバーレイ
